Chapter 11

Testing, clippy, fmt

Tests in this crate live next to the code they exercise, run in seconds, and — per war story #4 — caught a real concurrency bug that live traffic had been quietly masking. This chapter is about how they're built to do that reliably.

Inline unit tests

#[cfg(test)] mod tests at the bottom of a file compiles a nested module only when running tests — zero footprint in a release binary. Inside it, #[test] marks a function as a test case, and the standard assert!/assert_eq! macros take an optional trailing format-string argument for a custom failure message, the same format_args! machinery from chapter 10. A deterministic strategy test:

lb/src/strategy.rs — round_robin_cycles
#[test]
fn round_robin_cycles() {
    let backends = vec![backend(1), backend(2), backend(3)];
    let sel = Selector::new(Strategy::RoundRobin, 1);
    let picks: Vec<_> = (0..6)
        .map(|_| sel.select(&backends, ip()).unwrap().addr().port())
        .collect();
    assert_eq!(picks, vec![1, 2, 3, 1, 2, 3]);
}

An error-path test using unwrap_err (the trait-bound war story from chapter 6 is what makes this even compile):

lb/src/config.rs — rejects_duplicate_backends
#[test]
fn rejects_duplicate_backends() {
    let err = parse(args(&["--backends", "127.0.0.1:1,127.0.0.1:2,127.0.0.1:1"])).unwrap_err();
    assert!(err.contains("more than once"), "got: {err}");
}

and a parser-safety test feeding deliberately truncated bytes into quic::parse_header, already shown in full in chapter 10.

Async tests with real sockets, no mocks

#[tokio::test] is #[test]'s async sibling: it spins up a tokio runtime around the test body so you can write async fn tests directly and .await inside them:

#[tokio::test]
async fn sticky_sessions_and_round_robin_distribution() {

The balancer's integration tests don't mock the network at all — they spin up real UDP sockets bound to port 0 (the OS picks a free ephemeral port) as stand-in backends, tag every reply so the test can tell which backend answered, and drive real traffic through a real Balancer:

lb/src/balancer.rs — spawn_tagged_echo
async fn spawn_tagged_echo(tag: u8) -> SocketAddr {
    let sock = UdpSocket::bind("127.0.0.1:0").await.unwrap();
    let addr = sock.local_addr().unwrap();
    tokio::spawn(async move {
        let mut buf = [0u8; 2048];
        loop {
            let Ok((n, peer)) = sock.recv_from(&mut buf).await else {
                return;
            };
            let mut reply = Vec::with_capacity(n + 1);
            reply.push(tag);
            reply.extend_from_slice(&buf[..n]);
            let _ = sock.send_to(&reply, peer).await;
        }
    });
    addr
}

This is a deliberate trade: real sockets are slightly slower than a mock and mean the tests touch the loopback network stack, but they exercise the actual code path war story #4 broke — a mock upstream socket would never have reproduced a tokio reactor readiness-caching bug, because the bug lived in the real I/O layer the mock would have replaced.

Determinism without sleeps

Tests that talk to real sockets need real discipline to stay non-flaky. Three tactics recur throughout this suite. Bounded timeouts instead of assuming a reply arrives:

let (n, _) = timeout(Duration::from_secs(2), client.recv_from(&mut buf))

Polling with a deadline instead of a fixed sleep, when a test needs to wait for an async side effect (a metric to update) rather than a direct reply:

lb/src/balancer.rs — rejects_new_sessions_when_pool_is_down
let deadline = Instant::now() + Duration::from_secs(2);
loop {
    if h.metrics.sessions_rejected.load(Ordering::Relaxed) >= 2 {
        break;
    }
    assert!(Instant::now() < deadline, "rejections never counted");
    tokio::time::sleep(Duration::from_millis(20)).await;
}

A fixed sleep(500ms) here would either waste time when the assertion is true almost immediately, or flake under load when it isn't true quite that fast — polling with a deadline is fast in the common case and still reliably fails within a bounded time in the broken case. And tagged replies — each fake backend prefixes every reply with a distinguishing byte (spawn_tagged_echo, above) — let a test assert exactly which backend a session landed on without needing separate sockets or ports to tell them apart by address alone.

Test-driven bug discovery, reprised

Chapter 9 told the try_send readiness story in full: the bug was invisible in the make lb-demo live-traffic scenario, because real QUIC clients retransmit an unanswered Initial packet and the dropped-first-packet symptom silently healed itself. It surfaced instead as a hard, reproducible integration-test failure — a bounded timeout with no retransmission logic to mask the drop. That's the general shape of why these tests exist in this form: demos show you the happy path working; deterministic, no-retry tests show you the edge the happy path was quietly stepping around.

Tooling culture: clippy and fmt

cargo clippy is a much deeper lint pass than the compiler's own warnings — categories like redundant clones, manual loops that could be an iterator adapter, or needless returns. This crate is clippy-clean; running it as part of your workflow (many teams wire it into CI) catches these before they're habits. cargo fmt applies one canonical formatting with no configuration knobs worth arguing about — the Rust equivalent of gofmt, and for the same reason: mechanical style is a solved problem, and a formatter is cheaper than a code-review comment thread about brace placement.

Try it

Run cargo clippy --all-targets and cargo fmt --check inside lb/ (via make lb-test or directly) and confirm both are clean. Then introduce one obvious clippy target — e.g. add a .clone() immediately before a value's last use, or write a manual for i in 0..v.len() {{ ... v[i] ... }} loop somewhere — and see which lint fires. Revert before moving on.
