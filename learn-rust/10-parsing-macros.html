Chapter 10

Parsing bytes and macro_rules!

Two unrelated-looking topics share a chapter because they're both about doing more with less machinery: parsing untrusted bytes with nothing but bounds-checked slice access, and generating repetitive code with macro_rules! instead of a code generator or a runtime reflection trick.

Parsing untrusted bytes without unsafe

This load balancer sticks sessions to the client's 4-tuple, so it never strictly needs to understand QUIC's wire format — but peeking at the header lets it count new connections for metrics, and the parser is a compact demonstration of a broader point: Rust can do untrusted, bounds-checked bit-parsing with zero unsafe anywhere in the whole crate. Here's the whole function:

lb/src/quic.rs — parse_header
pub fn parse_header(datagram: &[u8]) -> Option<Header> {
    let first = *datagram.first()?;
    let long = first & 0x80 != 0;
    if !long {
        return Some(Header::Short);
    }

    // Long header: 1 byte + 4-byte version + length-prefixed DCID and SCID.
    let version = u32::from_be_bytes(datagram.get(1..5)?.try_into().ok()?);

    let dcid_len = *datagram.get(5)? as usize;
    let dcid_start: usize = 6;
    let dcid_end = dcid_start.checked_add(dcid_len)?;
    let dcid = datagram.get(dcid_start..dcid_end)?.to_vec();

    // Confirm the SCID length byte and bytes are actually present, so a truncated
    // packet is rejected rather than reported as a valid long header.
    let scid_len = *datagram.get(dcid_end)? as usize;
    let scid_end = dcid_end.checked_add(1)?.checked_add(scid_len)?;
    let _ = datagram.get(dcid_end + 1..scid_end)?;

    let packet_type = if version == 0 {
        None // Version Negotiation packet.
    } else {
        Some(match (first & 0x30) >> 4 {
            0x00 => LongPacketType::Initial,
            0x01 => LongPacketType::ZeroRtt,
            0x02 => LongPacketType::Handshake,
            _ => LongPacketType::Retry,
        })
    };

    Some(Header::Long {
        version,
        packet_type,
        dcid,
    })
}

Every single field read goes through slice.get(range)? rather than direct indexing (slice[range], which panics on an out-of-range index). get returns an Option, and the ? operator (chapter 5, here working on Option instead of Result — both support it) turns "the slice doesn't extend that far" into an immediate return None. A truncated or hostile datagram can never cause a panic or an out-of-bounds read; it just produces None, handled by the caller as "doesn't look like QUIC, forward it anyway":

lb/src/quic.rs — truncated_long_header_is_none
#[test]
fn truncated_long_header_is_none() {
    // Claims a 5-byte DCID but the packet ends early.
    let pkt = [0xC0, 0x00, 0x00, 0x00, 0x01, 0x05, 0xAA];
    assert_eq!(parse_header(&pkt), None);
}

Fixed-width integer fields come out with from_be_bytes plus try_into to convert a variable-length slice into the fixed-size array the conversion needs:

let version = u32::from_be_bytes(datagram.get(1..5)?.try_into().ok()?);

and variable-length fields chain checked_add (chapter 2's inference war story) to compute the next offset without risking an integer overflow panic on hostile input:

lb/src/quic.rs — parse_header
let dcid_len = *datagram.get(5)? as usize;
let dcid_start: usize = 6;
let dcid_end = dcid_start.checked_add(dcid_len)?;
let dcid = datagram.get(dcid_start..dcid_end)?.to_vec();

The bit-twiddling itself — first & 0x80, (first & 0x30) >> 4 — reads exactly like the equivalent C or Go would. What's different is everything around it: there's no way to read past the end of datagram, full stop, regardless of how malformed the input is.

Declarative macros: why logging needs one

A logging call needs to accept a variable number of format arguments (info!("backend {} recovered -> {}", label, state)) and, ideally, avoid paying the cost of formatting the message at all when that log level is disabled. Neither is possible with an ordinary function in Rust — functions have fixed arity, and arguments are evaluated before the call regardless of what the function does with them. macro_rules! solves both: it operates on the call's token stream before type-checking, so it can accept any number of arguments and expand into code that only formats when needed. log.rs defines the whole logging macro family in about twenty lines:

lb/src/log.rs — log_at! and friends
#[macro_export]
macro_rules! log_at {
    ($lvl:expr, $($arg:tt)*) => {
        $crate::log::emit($lvl, format_args!($($arg)*))
    };
}

#[macro_export]
macro_rules! debug {
    ($($arg:tt)*) => { $crate::log_at!($crate::log::Level::Debug, $($arg)*) };
}
#[macro_export]
macro_rules! info {
    ($($arg:tt)*) => { $crate::log_at!($crate::log::Level::Info, $($arg)*) };
}
#[macro_export]
macro_rules! warn {
    ($($arg:tt)*) => { $crate::log_at!($crate::log::Level::Warn, $($arg)*) };
}
#[macro_export]
macro_rules! error {
    ($($arg:tt)*) => { $crate::log_at!($crate::log::Level::Error, $($arg)*) };
}

$($arg:tt)* matches "zero or more arbitrary token trees" — the variadic part. Each level macro (info!, warn!, ...) just forwards its arguments to log_at! with its own Level spliced in, and log_at! forwards to emit via format_args!, which builds a lazily-formatted Arguments value rather than an eagerly-allocated String — the message is only actually rendered to text inside emit, after the level check has already passed. #[macro_export] makes the macro usable from other modules via $crate::log_at!, the macro equivalent of pub.

You've now met several macros without necessarily clocking them as such: #[derive(...)] (chapter 6), vec![...] and format! (chapter 2), and matches! (chapter 4) are all macros too — some declarative like this one, some built into the compiler. Rust also has procedural macros (how #[derive(Debug)] itself is implemented, for instance) — out of scope here; recognizing that they exist is enough for reading this codebase.

Macros before modules

Order matters at the top of main.rs:

#[macro_use]
mod log;

#[macro_use] has to appear directly above the mod log; declaration, and mod log; has to come before any other module that wants to use info!/warn!/etc. without a fully-qualified crate::log_at! path. Macro visibility follows textual declaration order in a way ordinary item visibility (governed by pub, not position) does not — a sharp edge if you're used to import order never mattering.

Try it

In lb/src/quic.rs, change the truncated-packet test's byte array in truncated_long_header_is_none to include one extra trailing byte so the packet is no longer actually truncated, and predict whether the assertion should now expect Some or stay None before running cargo test to check yourself. This exercises exactly the boundary the slice.get(range)? pattern is built to guard.
