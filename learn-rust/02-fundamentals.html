Chapter 02

Bindings, types, expressions

This chapter covers the parts of Rust that feel closest to what you already know — bindings, scalars, control flow, functions — while flagging the handful of places Rust insists on more precision than Go does. Ownership, the actually novel part, is next chapter.

Bindings: let, mut, shadowing

let introduces a binding that is immutable by default — the opposite default from Go's var/:=. You opt into mutability explicitly with let mut. This shows up constantly in config.rs::parse, which builds up a Config from defaults that individual flags then override:

lb/src/config.rs — parse
let mut listen = Config::default_listen();
let mut backends_raw: Option<String> = None;
let mut strategy = Strategy::RoundRobin;
let mut metrics_addr: Option<SocketAddr> = Some("127.0.0.1:9106".parse().unwrap());
let mut idle_timeout = Duration::from_secs(300);
let mut health_active = true;
let mut health_interval = Duration::from_secs(2);
let mut health_timeout = Duration::from_millis(500);
let mut health_fail_threshold: u32 = 2;
let mut log_level = Level::Info;

Every one of those needs mut because the flag-parsing loop that follows reassigns them as it consumes --listen, --backends, and so on. Bindings that never change — the vast majority in most Rust code — don't get the keyword, and the compiler warns if you wrote mut on something you never actually mutate. That's a cheap, continuous correctness signal Go's var can't give you.

Rust also permits shadowing: rebinding the same name with a new let, which introduces a genuinely new binding (possibly a new type) rather than mutating the old one. It's common for "parse this string into a stricter type under the same name" idioms; worth recognizing as distinct from mut when you see it in other Rust code.

Type inference, and when it needs an anchor

Rust infers types locally from usage, so most bindings need no annotation. But inference works forward from a value and backward from how it's used — and when neither side pins down a concrete type, the compiler stops and asks.

War story: inference needs an anchor

While writing the QUIC header parser, this line looked obviously fine:

lb/src/quic.rs — before
let dcid_len = *datagram.get(5)? as usize;
let dcid_start = 6;
let dcid_end = dcid_start.checked_add(dcid_len)?;

and it failed with:

error[E0689]: can't call method `checked_add` on ambiguous numeric type `{integer}`

Diagnosis: a bare integer literal like 6 doesn't have a type yet — Rust picks a default (i32) only when nothing else constrains it, and usize::checked_add needs to know it's operating on a usize specifically, so the literal's type stayed ambiguous right up to the method call. Fix: anchor it with an explicit annotation:

lb/src/quic.rs — parse_header
let dcid_len = *datagram.get(5)? as usize;
let dcid_start: usize = 6;
let dcid_end = dcid_start.checked_add(dcid_len)?;

Lesson: when Rust can't infer a numeric type, it doesn't guess wrong silently the way an untyped Go constant might convert unexpectedly at a boundary — it stops and makes you say what you meant, once, at the point of ambiguity.

Scalar types and casts

The integer types are explicit about width and signedness: u8…u64, u128, signed i8…i128, and the pointer-sized usize/isize used for indexing and lengths (Go's int plays that role implicitly; Rust makes you pick). There's no implicit numeric conversion anywhere, even between u32 and u64 — you convert explicitly with as, which truncates or extends without panicking:

lb/src/strategy.rs — Selector::select
Strategy::Random => {
    let r = self.next_rand() as usize;
    healthy[r % healthy.len()]
}

next_rand() returns a u64; as usize truncates it to the platform's pointer width before it's used to index the healthy-backend slice via modulo. Casts are a place bugs like to hide (silent truncation), so they're a good place to slow down when reading unfamiliar Rust.

Fixed-size arrays and growable Vecs are distinct types — an array's length is part of its type. A probe packet is always exactly PROBE_LEN bytes, so it's an array:

let mut pkt = [0u8; PROBE_LEN];

while a per-datagram scratch buffer sized from a runtime constant is a Vec:

let mut buf = vec![0u8; MAX_DATAGRAM];

String (owned, growable, heap-allocated) versus &str (a borrowed view into UTF-8 text, no allocation) is the same distinction as Vec vs. a slice, specialized to text. Backend owns its label as a String but exposes it as &str:

label: String,
lb/src/backend.rs — Backend::label
pub fn label(&self) -> &str {
    &self.label
}

Chapter 3 covers exactly why the getter can hand out a borrowed &str here without copying the string or fighting the borrow checker.

Expressions vs. statements

In Rust, blocks are expressions: the last line without a semicolon is the block's value. That makes if/else usable as an expression directly, not just a control-flow statement — both arms must produce the same type:

lb/src/net.rs — wildcard_for
pub fn wildcard_for(peer: SocketAddr) -> SocketAddr {
    if peer.is_ipv4() {
        "0.0.0.0:0".parse().unwrap()
    } else {
        "[::]:0".parse().unwrap()
    }
}

Both branches are single-expression blocks (a string literal parsed to a SocketAddr); the whole if/else is itself the function's return value, with no explicit return needed. match works the same way as an expression:

lb/src/log.rs — Level::label
fn label(self) -> &'static str {
    match self {
        Level::Debug => "DEBUG",
        Level::Info => "INFO",
        Level::Warn => "WARN",
        Level::Error => "ERROR",
    }
}

Every arm evaluates to a &'static str, so the whole match evaluates to one, and that's what the function returns. You'll see this pattern — "the function body is one big expression" — constantly in idiomatic Rust; get comfortable reading a match or if as a value-producing expression, not a jump table.

Functions and closures

fn name(params) -> ReturnType { ... }; as above, the last expression (no semicolon) is the return value — an explicit return is only needed for an early return. Closures are anonymous functions that can capture their environment, written with |params| body. config.rs::parse defines one inside its flag-parsing loop:

lb/src/config.rs — parse
let mut value = || -> Result<String, String> {
    it.next()
        .ok_or_else(|| format!("flag {flag} requires a value"))
};

value captures it (the argument iterator) and flag (the current flag string) from the enclosing scope by reference, and is called as value()? wherever a flag needs its argument — e.g. --listen calls parse_addr(&value()?)?. The comment above it in the source explains why it's a closure rather than a free function: a plain function can't capture it and flag from its caller's stack the way a closure can.

Loops and ranges

loop is an unconditional loop (broken with break, optionally returning a value); while cond { } is a conditional loop; for x in iter consumes anything implementing IntoIterator — no C-style three-clause loop exists in Rust at all. A plain while, draining a socket's queued packets:

while sock.try_recv(&mut buf).is_ok() {}

A for loop over a split-and-trim iterator, from backend-list parsing:

lb/src/config.rs — parse_backends
for token in raw.split(',') {
    let token = token.trim();
    if token.is_empty() {
        continue;
    }
    out.push(parse_addr(token)?);
}

Ranges (0..n, exclusive of n; 0..=n inclusive) are themselves iterators, so for i in 0..6 or (0..6).map(...) both work — strategy.rs's round-robin test drives six selections this way: (0..6).map(|_| sel.select(&backends, ip()).unwrap()...).

const and static

const is a compile-time-inlined value with no fixed memory address — closest to Go's typed constants. static has one fixed address for the whole program's lifetime, which is what makes it usable for shared mutable state via atomics (a preview of chapter 8):

const PROBE_VERSION: u32 = 0x1a2a_3a4a;
const MAX_DATAGRAM: usize = 64 * 1024;
static MIN_LEVEL: AtomicU8 = AtomicU8::new(Level::Info as u8);

MIN_LEVEL in log.rs is how the whole crate's log level is readable and writable from any thread without a lock — log::set_level stores into it, every info!/warn! call loads from it. More on why that's safe in chapter 8.

Try it

In lb/src/quic.rs, temporarily change let dcid_start: usize = 6; back to let dcid_start = 6; and run cargo build inside lb/. Read the E0689 error the compiler gives you, then revert the change. Reproducing war story #1 yourself is the fastest way to recognize the shape of an inference error the next time you hit one.
