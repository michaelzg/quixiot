Chapter 04

Enums, match, Option

Rust's enum is a tagged union: each variant can carry its own data, the compiler always knows which variant a value is, and match is the tool for acting on that — with a guarantee Go's switch doesn't make.

Enums with data

A plain, C-like enum — no payload, just a closed set of named values — looks like Strategy:

lb/src/strategy.rs — Strategy
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Strategy {
    RoundRobin,
    LeastConnections,
    Random,
    IpHash,
}

A richer enum can give each variant its own shape. QUIC's packet header is either a short form with no extractable fields, or a long form carrying a version, an optional packet type, and a connection ID — so Header is one enum with one unit-like variant and one struct-like variant:

lb/src/quic.rs — Header
#[derive(Debug, PartialEq, Eq)]
pub enum Header {
    /// Short header (1-RTT). The DCID length is implicit on the wire, so we
    /// can't extract it here — we only note the form.
    Short,
    Long {
        version: u32,
        packet_type: Option<LongPacketType>,
        dcid: Vec<u8>,
    },
}

There's no equivalent single-type representation in Go: you'd reach for an interface with two implementing structs, or a struct with a discriminant field and a pile of fields that are only valid for some discriminants (and nothing stops you from reading them when they aren't). Header makes invalid states unrepresentable — a Header::Short value has no dcid field to accidentally read, because that field doesn't exist on that variant.

match: exhaustiveness as a refactoring superpower

match requires you to handle every variant (or an explicit _ wildcard). This isn't just a style nicety — it's a compile error, and that turns "add a new variant" into a checklist the compiler runs for you. Selector::select matches on self.strategy:

pub fn select(&self, backends: &[Arc<Backend>], client: IpAddr) -> Option<Arc<Backend>> {
lb/src/strategy.rs — Selector::select
let chosen = match self.strategy {
    Strategy::RoundRobin => {
        // fetch_add wraps; modulo maps it onto the healthy subset. Note
        // the cursor counts *attempts*, not backends, so as backends flap
        // healthy/unhealthy the distribution stays roughly even.
        let n = self.rr_cursor.fetch_add(1, Ordering::Relaxed);
        healthy[n % healthy.len()]
    }
    Strategy::LeastConnections => healthy
        .iter()
        .min_by_key(|b| b.active_sessions())
        .copied()
        .expect("healthy is non-empty"),
    Strategy::Random => {
        let r = self.next_rand() as usize;
        healthy[r % healthy.len()]
    }
    Strategy::IpHash => {
        // Deterministic per client IP: the same device maps to the same
        // backend as long as that backend stays healthy.
        let h = hash_ip(client) as usize;
        healthy[h % healthy.len()]
    }
};

Add a fifth Strategy variant (chapter 12's weighted-strategy exercise asks you to) and this match, Strategy::label's match, and Strategy::parse's all stop compiling until you handle the new case everywhere. Nothing silently falls through to a default; nothing ships half-implemented.

Option<T>: no null

There is no null pointer, no nil interface value, and no reference type in Rust that can secretly be absent. "This might not have a value" is instead a real type, Option<T>, with two variants: Some(T) and None. Selector::select's signature says exactly this — it returns Option<Arc<Backend>>, and "every backend is currently unhealthy" is a real, typed outcome (the None case), not a null the caller can forget to check and panic on three call frames later. The caller in balancer.rs::get_or_create is forced by the type system to handle it:

lb/src/balancer.rs — Balancer::get_or_create
// Choose a backend and open the upstream socket *before* taking the lock
// again, so the await points don't hold the mutex across .await.
let backend = match self.selector.select(&self.backends, client.ip()) {
    Some(b) => b,
    None => {
        self.metrics.session_rejected();
        // swap returns the previous value, so exactly one caller wins
        // the edge and warns; the rest stay at debug until recovery.
        if !self.pool_down_warned.swap(true, Ordering::Relaxed) {
            warn!(
                "no healthy backend for new client {client}; dropping packets \
                 (suppressing further warnings until the pool recovers)"
            );
        } else {
            debug!("no healthy backend for new client {client}; dropping packet");
        }
        return None;
    }
};

There's no path through this function that silently treats an empty pool as a valid backend — the compiler won't let backend be used past this point unless this match has proven it's the Some case.

Go contrast

Go's nil can hide inside almost any type — a pointer, a map, a slice, an interface — and the type system gives you no help remembering to check for it; a forgotten nil check is a runtime panic, discovered in production if you're unlucky. The ok idiom (v, ok := m[k]) is the closest analogue to Option, but it's a convention, not enforced — you can ignore ok and use a zero-valued v and the compiler says nothing. Go's switch on a type or a closed set of constants also has no exhaustiveness check: add a new case and every switch that should handle it keeps compiling, silently falling into whatever default (or nothing) was already there.

Patterns beyond match

if let PATTERN = value { } handles one variant without a full match. let ... else (stabilized more recently) is its mirror image: match a pattern, or diverge (return/break/continue/panic!) in the else branch, and the matched bindings stay in scope for the rest of the function. A test helper in the balancer suite uses exactly this to bail out of an echo-server loop when its socket closes:

lb/src/balancer.rs — spawn_tagged_echo
let Ok((n, peer)) = sock.recv_from(&mut buf).await else {
    return;
};

while let is the loop form of if let: keep looping as long as the pattern keeps matching. The flag-parsing loop in config.rs is a while let over the argument iterator:

while let Some(flag) = it.next() {

and the matches! macro is a boolean one-liner for "does this value match this pattern," useful when you only care about yes/no:

lb/src/quic.rs — Header::is_initial
pub fn is_initial(&self) -> bool {
    matches!(
        self,
        Header::Long {
            packet_type: Some(LongPacketType::Initial),
            ..
        }
    )
}

The .. inside the pattern means "ignore the rest of this variant's fields" — here, ignore version and dcid, only packet_type matters for this check.

Option and Result combinators

Rather than unwrapping and re-wrapping by hand, Option/Result have chainable methods. parse_addr uses three in five lines:

lb/src/config.rs — parse_addr
fn parse_addr(s: &str) -> Result<SocketAddr, String> {
    s.to_socket_addrs()
        .map_err(|e| format!("bad address {s:?}: {e}"))?
        .next()
        .ok_or_else(|| format!("address {s:?} resolved to nothing"))
}

.map_err(...) transforms an Err's payload (a std io::Error) into this crate's error type (String) without touching an Ok. .next() on the resulting iterator of resolved addresses returns an Option (the standard iterator method, reused here instead of a special-cased "get first" function). .ok_or_else(...) converts that Option's None case into an Err with a lazily-built message — the closure only runs if it's actually needed. Chapter 5 covers Result and ? properly; the combinators are worth recognizing now because they show up constantly wherever this crate touches an Option.

Try it

In lb/src/strategy.rs, add a fifth line to the Strategy enum — say Weighted — and run cargo build inside lb/ without changing anything else. Read every non-exhaustive patterns error the compiler produces and note which functions it points you at (Strategy::label, Strategy::parse, Selector::select). This is the exhaustiveness check working exactly as designed — and the beginning of the weighted-strategy exercise in chapter 12.
