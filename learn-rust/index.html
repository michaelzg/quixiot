Guide

Learn Rust from a working load balancer

This is a Rust course where every example is production-shaped code pulled directly from lb/ in this repository — quixiot-lb, an L4 (UDP) load balancer that fronts one or more QuixIoT QUIC/HTTP3 servers. You will not see a single snippet invented for the tutorial. If a chapter shows you code, you can open the named file and find it verbatim.

You already know how to build software: you've shipped Go, you think in goroutines and channels, you don't need functions or hash maps explained to you. This guide skips that and goes straight at what's actually different about Rust — mostly the compiler's opinions about ownership, and what those opinions buy you.

What quixiot-lb does

quixiot-lb sits between clients and a pool of backend QUIC servers. The first UDP datagram from a new client address picks a backend (via a pluggable strategy), opens a dedicated upstream socket to it, and every later datagram from that client reuses the same session — which is what keeps a QUIC connection's packets landing on one backend, a hard requirement since a different backend has no idea about that connection. An idle sweeper evicts sessions that go quiet, and a Prometheus endpoint exposes the same metric families the rest of this repo uses.

It deliberately mirrors the Go impairment proxy in internal/proxy/proxy.go: same session-per-client forwarding model, same buffer sizing, same two-sided health checking — different language, different concurrency primitives. That makes the two worth reading side by side, and this guide does exactly that throughout, especially in chapters 3, 8, and 9.

How to use this guide

  • Read the chapters in order — each one leans on vocabulary from the last.
  • Run make lb-test to execute the crate's real test suite, and make lb-demo to watch three servers, the load balancer, and failover/recovery happen live. Nothing here is theoretical.
  • Every chapter ends with one Try it exercise against the real crate in lb/. Do them in a scratch branch; several ask you to (temporarily) break something to see the compiler or a test catch it.
  • Four callout types recur throughout: Go contrast (how you'd have written this in Go), Gotcha (a sharp edge worth knowing about early), War story (a real compiler error hit while building this crate, with the diagnosis and fix), and Try it (the exercise).
